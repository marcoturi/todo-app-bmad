## Challenges and Struggles

### 1. Boilerplate Landmines (3/5 stories)
Stale or broken boilerplate content was discovered in Stories 1.1, 1.2, and 1.4:
- Story 1.1: Stale GraphQL files, conflicting `packageManager` versions, invalid moon config fields
- Story 1.2: Stale `apps/api/docker-compose.yml` with wrong image and removed env vars
- Story 1.4: Broken `.releaserc pkgRoot: "client"`, orphaned `@semantic-release/exec` dep, double-registered `@semantic-release/git`

These were not budgeted for and consistently appeared as HIGH severity code review findings.

### 2. Repeated Biome Quote Style Violations (3/5 stories)
Stories 1.1, 1.2, and 1.3 all had the `edit_file` tool introduce double-quoted strings that Biome's `quoteStyle: single` rule rejected. Fixed each time via `check:fix`, but a recurring friction point.

### 3. HIGH Severity Findings Caught at Code Review, Not Dev Time (4/5 stories)
Implementations were functionally correct, but configuration and tooling details were consistently the blind spot:
- Coverage threshold left at 0% in Story 1.4 (directly contradicted AC #6)
- Real `@todo-app/shared` imports not verified in Story 1.3 (`pnpm check` passed vacuously)
- Missing `permissions` block on CI `release` job in Story 1.4
- Root cause: spec Dev Notes were detailed on *what* to implement but underspecified *configuration constraints* (e.g. "enforce a minimum" instead of "enforce exactly 10%")

### 4. Hand-Authored Shared Types Are the Wrong Pattern (Significant Discovery)
**Root cause identified by Marco during retrospective.**

`@todo-app/shared` currently contains hand-authored types (`Todo`, `CreateTodoRequest`, `UpdateTodoRequest`). The API defines its contract via Fastify TypeBox schemas, which `@fastify/swagger` can export as an OpenAPI spec. `openapi-typescript` (already in `apps/api/devDependencies`) can generate TypeScript types from that spec. Without this pipeline, the shared package and the runtime schema can drift silently.

The correct pattern:
```
TypeBox schema (Fastify) → @fastify/swagger → OpenAPI JSON → openapi-typescript → @todo-app/shared/src/generated/ → frontend + backend consumers
```

The tooling was already present (`openapi-typescript`, `generate:types` script in `apps/api`, `@fastify/swagger` registered) but the architectural intent was never made explicit in the story specs. This is a spec quality failure, not an implementation failure.

## Key Insights

1. **Spec quality is the primary improvement lever.** The Dev Notes section is doing heavy lifting but needs to be more prescriptive on configuration values and tooling decisions — not just structure and file locations.
2. **The right tooling was already there.** `openapi-typescript`, `generate:types`, and `@fastify/swagger` were present in the boilerplate but the architectural pattern was never connected in the specs.
3. **Boilerplate auditing needs to be an explicit subtask.** Any story that touches existing boilerplate should have a dedicated "audit for stale files, conflicting configs, orphaned dependencies" step before marking tasks complete.
4. **Dev notes propagation is a genuine strength** — the knowledge transfer mechanism between stories worked well and should be leaned into further.
