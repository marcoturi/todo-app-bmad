## Challenges

1. **React 19 concurrent mode** (Story 3.3) — `waitForLoadState('networkidle')` fires before React 19 commits DOM updates. E2E tests measured stale DOM state. Required switching to Playwright auto-retry assertions.

2. **Monorepo Docker complexity** (Story 3.5) — pnpm workspace resolution broke with per-app build context. Node 24 type stripping doesn't work in `node_modules`. Required Dockerfile rewrite, helper scripts, and shared package compilation workaround.

3. **Dev tooling interference with test infrastructure** (Stories 3.3, 3.6, 3.7) — MSW service workers intercepted Playwright a11y tests. Vitest picked up Playwright spec files. `vite-tsconfig-paths` didn't resolve aliases for excluded spec files.

4. **Pre-existing regressions surfaced during Docker build** (Story 3.5) — `<Text as="h1">` invalid in Radix UI, broken imports from spec files leaking into production bundle, PointerEvent mock cast issues.

5. **Biome violations in 4/8 stories** (3.1, 3.2, 3.4, 3.5) — Always caught in code review, never before. Pre-commit hook exists but isn't catching everything.

6. **Test assertion completeness** — Consistently insufficient on first pass across stories 3.1, 3.3, 3.4. Missing symmetric assertions, unverified payload values, inadequate DOM stability guards.

## Critical Finding: Runtime Verification Gap

**Marco's feedback (most important finding of this retro):**

Stories were being marked "done" without verifying the actual running system. This led to:

- **API regressions shipped undetected** — Marco had to fix broken API behavior multiple times during the epic
- **CI pipeline breaks after stories** — Pipeline broken after Story 3.8, requiring a separate fix session
- **Test suites passing ≠ working software** — 93% coverage didn't prevent real integration failures

**Root cause:** Dev agents relied on test suites as a proxy for "it works" without launching the app and checking API responses and UI behavior in the browser.

**Resolution:** Two new mandatory rules added to `project-context.md`:
1. Verify running application via Chrome DevTools MCP before marking any story done
2. Verify CI pipeline passes before marking any story done

## Key Lessons for Future Projects

1. **Advisory rules fail; structural enforcement works.** Proven across three epics. Rules encoded in `project-context.md` with clear prohibitions are followed; process agreements drift.

2. **Test suites are not a substitute for runtime verification.** High coverage (93-96%) did not prevent API regressions or broken pipelines. Always verify the running system.

3. **Dev Notes propagation eliminates knowledge rediscovery.** Documenting gotchas and anti-patterns inside story files enables clean knowledge transfer across stories and agents.

4. **Tests belong inside feature stories, not as standalone work.** Embedding tests as ACs produces higher organic coverage and catches issues earlier.

5. **React 19 concurrent rendering changes E2E assumptions.** `networkidle` is unreliable for DOM readiness. Use framework-aware waiting strategies (auto-retry assertions).

6. **Monorepo Docker builds require careful workspace dependency management.** pnpm workspaces, TypeScript type stripping, and multi-stage Docker builds have non-obvious interactions.
